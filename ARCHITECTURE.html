Layer Breakdown

Domain (Backend.Domain)
Pure business logic, zero framework dependencies. Defines:
  • Entities (Fic, User) with validation logic
  • Repository interfaces (contracts)
  • Domain exceptions
  • Value objects (Email, JwtToken)
Nothing in Domain imports EF Core, Postgres, or HTTP types.
Application (Backend.Application)
Business logic orchestration and use cases. Depends only on Domain:
  • Services (AuthService, FicService, WrappedStatsService)
  • DTOs for API contracts (RegisterDto, FicResponseDto)
  • Input validation (FluentValidation)
  • Mapper config (AutoMapper)
Services call IFicRepository (interface), never DbContext directly.
Infrastructure (Backend.Infrastructure)
External implementations and data access. Depends on Domain + Application:
  • DbContext and EF Core configuration
  • Repository implementations (IFicRepository → FicRepository)
  • JWT token creation, password hashing
  • AO3 scraper (AngleSharp)
  • DependencyInjection folder with ServiceRegistration extension
All "how it's done" code lives here.
Api (Backend.Api)
HTTP layer and dependency injection. Depends on all three:
  • Program.cs wires up DI container
  • Endpoints/Controllers map HTTP requests to services
  • Middleware for cross-cutting concerns (exception handling, auth)
  • Configuration (appsettings.json)
Controllers/Endpoints are thin — they call services, never query the database.
Tests (Backend.Tests)
Unit + integration tests:
  • Unit: Service logic, validation (mocked dependencies)
  • Integration: Full endpoint → database flow (real or in-memory DB)
  • Fixtures: Reusable test data setup

Key Principles

  • Dependency rule: Only point inward (Api → Application → Domain)
  • Interface segregation: Define IFicRepository in Domain, implement in Infrastructure
  • Single responsibility: Services orchestrate, Repositories access data, Validators check input
  • No leaky abstractions: Entity classes don't reference DbContext; DTOs shield domain models from API changes
  • Testability: All services accept interface dependencies (Moq-friendly)
